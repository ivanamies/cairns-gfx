HUMAN TODO — kill the pimpl `Impl* impl_` heap indirection (make it compile-time):
  Every rhi subsystem (Device/Allocator/Resources/Bindless/Frames/CommandRecorder +
  the transitional ResourceManager) uses `struct Impl; Impl* impl_ = nullptr;` with a
  per-Init `new Impl()` + per-access pointer indirection. The ONLY thing pimpl buys is
  ABI/compile-firewall across a stable library boundary — which we do NOT have: the
  backend is fixed at COMPILE time (CAIRNS_METAL / CAIRNS_VULKAN) and these are
  engine-internal classes recompiled wholesale. The backend-typed fields already live in
  guarded internal headers (rhi/{metal,vulkan}/internal/*_impl.hpp). So the indirection
  is pure cost (a heap alloc per subsystem + a pointer hop per field access on the hot
  path) for zero benefit.
  Fix: make Impl a by-value member — `Impl impl_;` (the public header includes the
  internal Impl header under the backend #if), or fold the fields directly into the class
  under #if guards. Removes the heap alloc, the null-checks, and the indirection; all
  resolvable at compile time. Do it after the Phase-0 split lands (every subsystem then
  has a clean single Impl to inline). Watch: the public headers would then pull the
  guarded backend headers (Vk*/MTL::*) — keep that contained, or use a fixed-size
  aligned storage buffer if header hygiene matters more than simplicity.

DONE — Aaltonen slide 26 (Pack Meshes), now packed ACROSS all GLBs:
  1. Recorders select each primitive via baseVertex/baseIndex in the draw call and
     change-track the VB/IB binds (bind only when the mesh buffer changes).
  2. LoadScenesGpu co-allocates EVERY loaded GLB's verts in lockstep into ONE shared
     buffer set: one combined [positions | attributes] vertex buffer (sections adjacent,
     NOT interleaved, attr stream via a non-owning alias handle at the attr-section
     offset) + one shared index buffer. Every mesh of every scene shares those handles
     and prims carry an all-GLBs-global baseVertex/baseIndex. So ALL draws in the frame
     resolve to the same buffers and the recorder binds each stream ONCE PER FRAME
     (verified: 1 pos VB bind/frame; was once per GLB ~= 50). Byte-identical on metal.
  The earlier "vertex-quantized 128MB block" worry was wrong: a logical buffer never
  spans heap blocks -- AllocBuffer mints a dedicated OVERSIZED block when bytes >
  kHeapBlockBytes (block_bytes = padded + padded>>3 headroom for OffsetAllocator's
  round-up-to-bin). The combined buffer (259MB @50 GLBs, ~500MB @100) lives in one block;
  CreateBuffer's initial_data now stages in chunks through the 64MB kUpload ring
  (BumpRingBytes) instead of one oversized BumpAllocate.
  Bench (vk Release/no-val, 3300 instances):
    macOS MoltenVK @100 GLBs (11517 draws): frame ~5.2ms, build_draws ~1.84ms, record ~0.36ms.
    Android @50 GLBs (Galaxy S22 / SD 8 Gen 1, -O2 -DNDEBUG), warm: frame ~92.3ms,
      build_draws ~18.2ms, record ~17.0ms (~57ms GPU/present remainder).
  NOTE: resource aliasing (the hand-rolled attr_alias) is a stopgap -- proper aliasing
  with tracked lifetimes will come with the render-graph impl.

XX. SIM-TIME != REAL-TIME BUG (fixed-clock accumulator).
  The Fiedler accumulator in engine.hpp draw() (the kFixedDt loop) does:
    while (acc >= kFixedDt && steps < kMaxStepsPerFrame) { sim_angle_deg_ += rate*dt; ++sim_frame_; acc -= dt; }
    if (steps == kMaxStepsPerFrame && acc >= dt) { acc = 0; }
  When a render frame is slow (e.g. 10k actors) and the steps cap (kMaxStepsPerFrame=5) trips,
  we ZERO the accumulator -- which makes the sim run in SLOW MOTION relative to wall time.
  Observed: at high actor counts the world rotation perceptibly lags. Per the source plan that
  is "intentional, a slow-but-correct sim beats an unrecoverable lockup", but the user is
  right: animation/UI time shouldn't slow down just because the render frame is heavy.
  Options:
    (a) raise kMaxStepsPerFrame (5 -> 8/16); pay more CPU on slow frames.
    (b) split sim_time into TWO clocks: deterministic fixed-dt for physics (capped),
        and a real-time animation_time for rotation/animation that just uses Tick() directly
        (golden capture still pins it via FixedClock).
    (c) reset behavior on cap: instead of acc=0, set acc=dt (run exactly one step next frame)
        and accept a one-frame lag. Smoother visually than full slow-mo.
  My read: (b) is the right fix -- the fixed-clock plan conflated "all sim" with "deterministic
  physics-style sim"; rotation/anim don't need the latter and shouldn't slow down. Defer until
  we revisit determinism after skinning lands.
